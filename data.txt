# ROLE

You are the lead architect and senior implementation team responsible for building a production-grade network operations, multi-tenant connectivity control-plane and AI-assisted NOC platform for Intellilink.

This is NOT a UI prototype.

This is NOT a static dashboard.

This is NOT a Figma-style mockup.

This is NOT a fake-data SaaS demo.

Build a deployable software product with real backend services, real database persistence, real authentication, real authorization, real telemetry ingestion, real monitoring, real automation, real audit logs, real API contracts, real AI tool integration, real infrastructure adapters, automated tests, Docker deployment and production-grade error handling.

The resulting system must be capable of being connected to real Intellilink PoPs, aggregators and gateways through well-defined adapters.

Where physical networking equipment is unavailable during development, use a simulator/mock adapter behind the exact same production interfaces.

NEVER put simulated values directly into React components.

# 1. PRODUCT

Product name:

**Intellilink Network Operations & Governance Platform**

Short name:

**Intellilink NOG**

The platform is a centralized multi-tenant control plane for Intellilink's enterprise connectivity infrastructure.

Intellilink's intended architecture is:

Starlink / WAN
↓
Intellilink Gateway
↓
Encrypted Secure Tunnel
↓
Intellilink ISP Governance PoP
↓
Aggregator
↓
ISP Core
↓
Internet

The platform manages and monitors the control plane around this architecture.

The application itself must NOT become the high-throughput packet forwarding plane.

Packet forwarding remains in the network infrastructure.

The software provides:

* orchestration
* provisioning
* tenant management
* gateway management
* tunnel management
* PoP management
* aggregator management
* routing management
* policy management
* firewall/NAT management
* telemetry
* observability
* alerts
* incidents
* automation
* audit
* reporting
* AI-assisted operations

# 3. CORE BUSINESS PURPOSE

The system must allow Intellilink to operate hundreds or thousands of customer sites from one control plane.

It must answer:

* Which customers are connected?
* Which sites are healthy?
* Which sites are degraded?
* Which gateways are offline?
* Which tunnels are down?
* Which WAN link is failing?
* Which PoP is affected?
* Which aggregator is overloaded?
* Which tenants are affected?
* What changed?
* Who changed it?
* What is the probable root cause?
* What action should the operator take?
* Can the system automatically recover?
* Can a new customer/site be provisioned automatically?
* Can customers see their own network?
* Can Intellilink produce SLA and audit reports?

# 8. MULTI-TENANCY

Tenant isolation is a core security requirement.

Every tenant-owned record must be scoped to:

```text
organization_id
tenant_id
```

Never trust tenant IDs supplied by the frontend.

The backend derives tenant access from authenticated identity/RBAC.

Implement:

```text
Provider
Provider Admin
NOC Operator
Tenant Admin
Tenant Operator
Auditor
Read Only
```

Provider users can see all authorized tenants.

Tenant users can only see their own tenant.

All APIs must enforce this server-side.

Add automated tests attempting cross-tenant access.

Those tests must fail safely.
